- (decision) UX-01 resolved: the initial surface is an internal responsive web console for a single operator who also audits their own governed work; desktop/laptop supports the full flow and mobile is consultation-only.
- (decision) UX-02 resolved: the console inherits shadcn/ui as its visual system; no separate brand layer, framework, or custom palette was selected.
- (decision) UX-03 partially resolved: the console supports pt-PT, pt-BR, English, and Spanish; light and dark themes; keyboard and screen-reader operation. The target WCAG conformance level remains open.
- (decision) UX-05 resolved for the initial single-operator product: the operator may approve an eligible Override or Formal Exception in the same console, but only when the governing policy permits that approval.
- (event) Impeccable shape brief confirmed by the operator; UX spines updated from the confirmed brief while remaining open items stay partial.
- (decision) UX-01 reconfirmed: internal responsive web console; desktop/laptop supports the full flow, mobile remains consultation-only, with no change to the initial single-operator-per-Project model.
- (decision) UX-02 updated: the console inherits shadcn/ui and must use the approved local theme at docs/theme.css; no separate visual system is introduced.
- (decision) UX-03 resolved: accessibility target is WCAG 2.2 AA. Remaining quantitative interaction, motion, localization fallback, and regional-format details still require elicitation before finalization.
- (decision) UX-05 reconfirmed: the same operator may approve an eligible Override or Formal Exception only where governing policy grants that authority; there is no segregation-of-duties requirement for the initial product.
- (decision) UX-06 scope clarification: the intended tool constructs system code for third parties and is not intended to process customer databases. This does not remove the product's existing prohibition on exposing secrets or raw governed runner logs; the remaining UX exposure behavior requires confirmation.
- (decision) UX-04 resolved: audit consultation uses a list-first experience, not a graph in the MVP. Ledger supports ID/text search; filters for period, event type, entity, Stage Revision/Baseline, actor/origin, and result; time ordering; cursor pagination; and shareable URLs preserving the query. Traceability uses expandable relation lists/trees, breadcrumbs, open-in-Ledger links, and side-by-side revision/Baseline comparison. No export is offered in the MVP.
- (decision) UX-06 resolved: Evidence exposure in the MVP is metadata and governed references by default; previews are only for explicitly safe/redacted content; unavailable content displays the reason; downloads and exports are not offered. The product does not process third-party customer databases, but existing secret and raw-runner-log prohibitions remain in force.
- (decision) UX-07 resolved: the operator chooses automatic or manual downstream impact analysis at the applicable change/reopening point; the console shows progress while analysis runs. Relations are grouped in disposition order STALE, REQUIRES_REVIEW, then unchanged. STALE and REQUIRES_REVIEW create a navigable pending item for the dependent revision.
- (decision) UX-03 finalized: WCAG 2.2 AA is the conformance target. Dates, times, and numbers use the locale selected for pt-PT, pt-BR, English, or Spanish. Missing translations display the original content with a notice. The system reduce-motion preference removes nonessential animation. The product does not require an additional manual keyboard/screen-reader acceptance-test suite beyond the WCAG conformance target.
- (decision) UX-07 failure handling resolved: if downstream impact analysis fails or does not complete, the console shows a sanitized error, does not present an incomplete set as final, and lets the operator retry manually.
- (decision) Mock coverage decision: every IA surface is spine-only for this UX run; no visual reference/mockup is requested.
- (event) Reviewer Gate selected: rubric walker and accessibility lenses.
- (change) Validation remediation: manual impact analysis now creates a visible pending state and keeps dependent authorization/closure ineligible until each known relation has a disposition; failure preserves that guard and offers sanitized manual retry.
- (change) Accessibility remediation: the spines restrict approved theme token pairings to WCAG 2.2 AA-capable uses, add async status announcements and focus lifecycle, authorize/redact Evidence before all visual and accessibility-tree exposure, and specify reflow, language-of-parts, target-size, no-drag, and query-focus behavior.
